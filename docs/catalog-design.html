Collect ahead. Apply to the specific edit.

The collector and request path are separate. A request to improve button focus should load focused UI guidance, not select a new web framework.

  1. Background collection: 10/30/60 minute interval, dated GitHub Trending pages plus explicit skill repositories. Separate source provenance prevents confusing popularity with Trending membership.
  2. Incremental cache: metadata/commit, immutable tree, Git blob hash, prepared subtree fingerprint. Changed supporting resources invalidate readiness; changed instructions invalidate semantic review. Partial failures preserve prior evidence.
  3. Capability cards: instructions, README, source excerpts for situations/inputs/outputs/constraints, pinned evidence and optional host-reviewed semantic profiles. Literal evidence and version are validated. Extraction is not advertised as full semantic understanding.
  4. Local routing: host converts each operation to keywords and constraints. Local relevance ranks candidates, deduplicated by repository/name. Popularity does not override relevance. Host makes the final semantic decision and can abstain.
  5. Application: validate the prepared bundle offline, read only necessary references, apply guidance to the existing task, verify the artifact. Record candidate decisions and host-reported checks separately from executed apply receipts.

Operational limits

The collector caps each batch and rotates repositories and skill entries. Cold indexing and prewarming are expensive; a warm request does not initiate them. Missing license metadata excludes a routing candidate pending inspection. The catalog is not exhaustive, and copied skill variants may share a name. A crashed collector leaves a PID lock requiring operator inspection. Credential discovery by the optional worker uses gh in memory; tokens never enter catalog or logs. Local traces may include task intent, so use public keywords and manage their retention.

The repository supplies catalog-watch as a foreground worker and scripts/catalog-worker.mjs for an OS scheduler. On the maintainer's machine a separate user LaunchAgent was configured at 1800 seconds; this is not automatically installed for other users. No remote publishing or cloud job is required.
