수집은 중앙에서, 매칭은 사용자 곁에서

2026-11-07 KST. 상시 LLM이나 요청마다 새로운 검색 없이 운영하는 구조다. 운영자 수집 배치는 GitHub 변경분을 저장한다. 별도 로컬 에이전트 세션은 재분류 대기목록을 한정된 분량으로 읽고, 검증된 프로필을 저장한다. 읽기 서버는 공개 스냅샷만 제공한다.

검증관찰
공개 스냅샷904개 카드, 약 4.69MB. 로컬 경로·원문 지침·설치 경로·사용자 작업 기록 제외. 정밀 의미 검토 프로필 1개, 나머지는 원문 추출임을 유지.
실제 HTTP 서버GET /v1/catalog → 200, 동일 ETag 조건부 요청 → 304
새 사용자 캐시최초 요청 1회, 약 170ms. 재조회 요청 0회, 약 135ms. 모두 loopback 로컬 서버 실측으로, 인터넷 지연이나 LLM 판단·스킬 실행 시간은 포함하지 않는다.
요청 정보서버로 보내는 것은 카탈로그 GET뿐. 작업 의도·선택 근거·적용 결과는 로컬 trace 파일에 저장.
상시 추론수집기·조회 API에는 LLM API 호출 없음. 분류 대기목록은 catalog-review-queue, 유한한 로컬 검토 결과 반영은 catalog-label.

배포 상태

클라우드 배포는 완료되지 않았다. 현재 gcloud 인증 갱신은 invalid_grant로 실패했고 대상 프로젝트 ID도 지정되지 않았다. 기존 로컬 운영자 수집기는 중앙 배포 전까지 유지된다. 원격 배포와 정기 배치 성공을 확인한 뒤 중복 로컬 스케줄을 해제해야 한다.

호스팅 선택

Firebase Hosting에서 정적 JSON을 캐시해 제공할 수도 있고, Hosting과 Cloud Run을 연결해 읽기 API를 제공할 수도 있다. 예약 배치는 Cloud Scheduler 연동을 사용할 수 있으며, 프로젝트·요금제·권한을 확인한 뒤 실제 배포해야 한다.

현재 HTTP 연결은 MCP와 유사한 외부 지식 연결 방식이며 MCP 프로토콜 서버를 구현했다는 의미가 아니다. 선택된 스킬의 최초 다운로드·지원 파일 준비에는 별도 비용이 든다.
