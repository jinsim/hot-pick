Cloud collector migration

Design and verification · 2026-11-08 KST

The operator runs the incremental collector on standard GitHub-hosted Ubuntu runners in the public jinsim/hot-pick repository. Firebase Hosting continues serving the public catalog. Neither component invokes a model. No personal computer, service-account key, paid runner, Cloud Run service or paid Scheduler job is required.

Execution and state

A single workflow is scheduled at minutes 7 and 37 of each UTC hour, or by explicit manual dispatch. It does not run on pushes or pull requests. A non-cancelling concurrency group serializes publishers. Jobs have a 12-minute limit; collection has a smaller time budget and bounded repository/skill batches.

Restore only public GitHub HTTP responses, verified content-addressed blobs and the operator index. User requests, traces, prepared executable bundles and Google credentials are excluded from the cache. A cache miss seeds metadata from the validated live catalog, preserving existing coverage while hydrating source files in bounded batches. Cache eviction cannot erase the last public catalog.

Check mutable repository metadata/commit with ETags. Reuse unchanged commit inventories, source descriptions and blob hashes; changed commits inspect their trees and fetch only missing blobs. Incomplete inventories resume on later runs. Checkpoints are based on processed entries, avoiding repeatedly writing the whole index for every entry when total card count is divisible by ten.

Each batch checks at most eight repositories and processes at most forty skill entries per repository, with a six-minute collection budget. Daily, weekly and monthly Trending observations are refreshed each batch. Least-recently-attempted repositories rotate through the queue. A 30-minute schedule does not mean every indexed repository or every card is rechecked every 30 minutes; per-card timestamps retain that distinction.

Publication and access

Authenticate only after collecting. Google Workload Identity Federation accepts the numeric repository and owner IDs, main branch, exact collector workflow path, and schedule/manual events. Its service account can publish Hosting content in the dedicated project and consume that project's APIs. It has no billing, unrelated-project, or private-user-data access. Short-lived access tokens stay in the publisher step environment.

Validate and publish only the public snapshot. Failed upload/finalization preserves the previous release. Verify the deployed SHA-256 and conditional HTTP response. Retain ten Hosting releases, the latest three collector caches, and short workflow reports. Bound cached public data to 256 MiB before saving. The repository's existing 10 GiB cache allowance is not raised.

Cost and availability limits

Standard Actions runners in public repositories are free. Firebase remains without a linked billing account and is subject to free-plan quotas. No claim of unlimited hosting is made. GitHub schedules can be delayed or dropped under load and public-repository schedules can be disabled after inactivity; this is a low-cost periodic collector, not a real-time scheduling guarantee. Check the workflow's last successful run and catalog timestamp.

Cutover verification

The first cloud run completed all steps successfully. It preserved 1,600 public cards, processed 149 source entries in 24.755 seconds, and used a 5.3 MB compressed Actions cache. The local collector was then unloaded and disabled. All 65 local tests passed. Machine-readable evidence

The earlier absence of runs resolved without configuration changes, but this does not identify the exact reason for missed or delayed ticks. GitHub does not expose a per-missed-tick explanation here. Automatic refresh works; a strict 30-minute refresh promise is not supported by the observations.

Free-only operation: retain public standard Actions runners and Firebase Hosting without billing. Billing was rechecked as disabled; three compressed caches total 22,961,614 bytes. No paid scheduler, larger runner, billing linkage or paid fallback was added. On free-plan quota exhaustion, accept publication/serving interruption rather than enabling charges. The local launchd collector remains disabled.
