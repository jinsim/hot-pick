Architecture

A Cloudflare Worker Cron runs at minute 0 and 30 UTC (also minute 0 and 30 in Korea), independently of GitHub cron. It calls only the main branch's catalog.yml workflow dispatch endpoint. GitHub performs collection, cache restoration, validation and Firebase publication. Existing workflow_run monitoring handles publication failure and recovery. The existing 120-minute freshness threshold is unchanged. GitHub cron remains as a fallback.

HTTP 204 means dispatch was accepted, not that collection or publication succeeded. No scheduler can guarantee exact publication at minute 0 and 30: runner queuing, platform outages and free-quota exhaustion can delay it. Verify actual start/end times and the public catalog timestamp. This removes dependence on GitHub's cron trigger, not on its runners.

Credential boundaries

Use an existing Cloudflare account on Workers Free. Do not upgrade a plan or enable paid fallback. The API uploader refuses to run unless the operator explicitly verifies that plan. The CLI token could not read subscriptions, so the current Free plan was verified directly in the authenticated dashboard using the existing saved sign-in. No password value was revealed or stored by this project. Firebase billingEnabled=false was separately verified through its billing API.

Create a fine-grained GitHub credential restricted to jinsim/hot-pick, with Actions read/write and no Contents write, Issues write, or organization scope. GitHub Actions write also permits operations beyond dispatch within this one repository; GitHub does not offer a dispatch-only fine-grained permission. Review the scope and expiry before creation. Store it only as an encrypted Worker secret named HOT_PICK_DISPATCH_TOKEN. Never reuse the caller's broad gh OAuth token for the Worker. Never commit or publish any credential.

The uploader uses only explicitly supplied environment variables: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN, and HOT_PICK_FREE_PLAN_VERIFIED=true. HOT_PICK_DISPATCH_TOKEN is required only for first provisioning or explicit rotation. Redeployment checks and preserves the existing encrypted secret, then verifies it again before configuring Cron; it does not require creating or copying another credential. No token value is logged or served by the Worker. /health is public read-only; no public HTTP endpoint starts collection. CLI credentials and private repository code are not sent to catalog readers.
