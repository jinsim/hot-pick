Small index, selected details

2026-11-11. The free GitHub Actions collector now publishes a compact search index and content-addressed candidate details alongside the compatibility catalog in one Firebase release.

Architecture

  1. Validate the full public snapshot with the existing allowlist before accessing credentials.
  2. Derive index.json with the exact unique normalized matching terms, short descriptions, source pins and popularity evidence.
  3. Derive details/SHA256.json for each full public candidate profile. Hashes include all profile/provenance fields; unchanged content reuses its address.
  4. Publish all assets together using bounded batches and eight concurrent uploads. Finalize and release only after successful uploads.
  5. Route locally from index.json. Fetch only requested candidates through catalog-detail; verify SHA-256 and source commit/blob before returning evidence. Cache immutable detail bodies for offline access.

The existing catalog.json endpoint remains compatible. Opt into the new path with catalog-connect --catalog-url https://jinsim-hot-pick.web.app/index.json. No hidden fallback downloads the entire catalog. A cold offline detail fails explicitly. Details referenced by an old trace can disappear after publication if uncached; reroute in that case. Cached details retain their original evidence.

Cost and privacy

Public standard GitHub runners and billing-disabled Firebase Hosting remain in use. No paid service or LLM call is added. More small static files are published; unchanged hashes avoid repeated upload. Hosting retains ten releases, and free quotas still limit storage/traffic. User task text, traces and outcomes remain local. Credentials are never forwarded to detail endpoints.
