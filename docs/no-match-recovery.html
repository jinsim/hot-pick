From a catalog miss to an applied open-source result

Actual investigation and execution: 2026-11-27. Scope: fix missing-domain discovery and local outcome linkage, then verify a real pinned data application. No internal LLM, API key, paid resource, collector change or new background service.

What actually happened

The original local route at 03:26:19 UTC had two operations: Korean phoneme assessment (keywords korean, phoneme, alignment; required phoneme) and articulatory visualization (keywords articulatory, vocal tract; required articulatory). Both returned zero eligible indexed skills. The route stored no keywords, no rejection diagnostic and no linked host outcome.

Checking the original task chat corrected a misleading inference: its agent did continue with general GitHub source inspection and subsequently built a recording/visualization prototype. The trace's no_matches status was not evidence that no open source had been used. Its narrow meaning was a catalog retrieval miss. That distinction must remain visible to users and monitoring.

Replaying the same keyword/filter inputs against the updated 05:01:28 UTC catalog again returned no_matches. The deduplicated inventory contained 2,496 skill cards, and neither required term occurred in its searchable vocabulary. General speech/phonetics libraries are not comprehensively represented in that skill inventory. The bug was not solved by lowering relevance thresholds or promoting unrelated popular design tools.

Implemented request path

  1. Retain the original keywords and report missing required terms, inventory size and the next action.
  2. The caller supplies bounded public discovery_queries and invokes catalog-route with --discover. Only operations without catalog candidates trigger general GitHub/observed weekly-Trending discovery. Repeated queries share one cached search. Matched operations need no additional discovery.
  3. Preserve the indexed shortlist and hard filters. Separate general GitHub leads remain inspection_required, with no invented compatibility or Trending membership. Unknown licenses and explicitly excluded repositories are omitted.
  4. The caller inspects the selected repository at a fixed commit, acquires it, authors a task plan, applies it and checks actual artifacts.
  5. catalog-record links that selected repository, mandatory full commit pin, artifacts and checks to the same local route. Command receipts remain distinct from host-reported semantic judgments. Nothing is uploaded as telemetry.

At most two public queries per missing operation and four distinct queries per request are permitted. Without explicit public queries the result asks the caller to supply them, never transmits the private intent. Network failures and absent coverage stay explicit. Offline discovery uses verified cached responses only. Successful retrieval still does not establish successful application.

Real source selection and application

The public query phonological features retrieved PanPhon at a49c242, with 342 observed GitHub stars and an MIT license. No evidence of membership in the observed weekly Trending page was found. It was selected for its IPA-to-articulatory-feature dataset and practical offline integration, not fabricated popularity.

The reproducible application reads the pinned CSV after checking its Git blob hash, computes differences across 24 source features, and writes JSON plus an HTML feature visualization. It uses the dataset directly with Python's standard library; it does not claim to execute PanPhon's Python API. The full dataset and library dependencies are not vendored.

Measured behavior and limits

Single warm observations on the same catalog: local-only miss 197ms, enriched route 219ms, offline enriched route 212ms. The enriched warm route made zero HTTP requests and reused three cached responses (index, GitHub search and weekly Trending). These are individual functional observations, not a controlled benchmark, billed token measurement or proof of lower total task time. An uncached fallback still needs network retrieval; source inspection and application also take work.

100 repository tests passed, including filter preservation, partial coverage, public-query boundaries, deduplicated fallback, search failure, exclusion/license filtering, bounded query budgets and pin-required outcome recording. Skill validation passed. The Python integration checks and rendered artifact were separately verified.

This is an IPA feature-comparison component, not an automatic pronunciation diagnosis service, anatomical tongue inference, Korean G2P or a validated clinical score. Original prototype files were not overwritten: another active task is maintaining them. The original route is preserved unchanged; the new route records this verified application.
