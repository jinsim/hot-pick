작업에서 GitHub 오픈소스의 실제 적용까지

2026-11-07 · hot-pick v0.2 설계

사용자의 작업을 호스트 LLM이 해석하고, CLI는 출처와 실행 증거를 제공한다. 스킬 검색 기능은 유지하면서 일반 저장소를 위한 discover, trending, repo, read, acquire, apply 명령을 추가한다.

  1. GitHub repository search로 관련 후보를 발견하고 실제 Trending HTML에서 관찰한 최근 인기와 결합한다. 높은 누적 스타를 Trending으로 표시하지 않는다.
  2. 커밋에 고정된 README, 라이선스와 패키지 manifest, 필요한 추가 문서를 읽어 선택 근거와 적용 조건을 확보한다. 불완전한 검색·HTML 변경·요청 실패는 명시한다.
  3. 선택한 저장소를 작업 공간에 고정 커밋으로 가져온다. 다운로드와 실행을 분리한다.
  4. 호스트가 작성·검토한 로컬 JSON 계획으로 설치·작업·검증 명령을 실행하고 결과 파일 해시와 실행 기록을 남긴다. README에서 명령을 추출해 임의 실행하지 않는다. 성공은 명시적인 검증 통과와 결과물 존재를 모두 요구한다.
  5. 실제 Trending 프로젝트를 사용해 서로 다른 구조의 상품 HTML 두 개를 JSON으로 추출하고 예상값과 비교한다. 실패 입력도 검증한다.

기존 캐시를 재사용한다. 조회 시각과 데이터 확인 시각을 구분한다. 10분은 캐시 갱신 주기이며 이번 구현은 숨겨진 주기 실행 서비스를 등록하지 않는다. Trending은 공개 HTML 어댑터여서 마크업 변경에 취약하고 전체 생태계 순위가 아니다. 로컬 프로세스 실행은 보안 샌드박스가 아니며 사용자 권한·작업 범위를 따른다.
