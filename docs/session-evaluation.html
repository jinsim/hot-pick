Independent task-session evaluation

Actual evaluation date: 2026-11-11. Git display dates do not determine these measurement timestamps.

Fresh Codex CLI processes, identical task seeds and prompts except Hot Pick instructions, the existing configured gpt-6.1-sol/high model, and held-out deterministic checks. Raw usage comes from turn.completed events, not text-length estimates. Agents completed actual code edits; artifacts and the harness are included.

Original paired result

Both arms passed 43/43 predeclared checks across four tasks. Baseline sessions totalled 307.50 seconds, 471,849 input tokens and 9,460 output tokens. Original Hot Pick totalled 774.09 seconds, 1,838,682 input tokens and 24,396 output tokens. No acceptance-quality gain was measured; discovery and inspection added substantial overhead in this sample.

Development retests retain the first revision’s mixed results: CSV had lower total input but took longer and produced more output; pagination improved versus original Hot Pick but remained slower than baseline; UI’s first retest increased input substantially. The second UI revision is an adaptive development retest of generic verification-batching guidance, not an independent replication or a replacement for that regression. No zero-network direct-work choice was observed in the first three retests.

The second UI revision reduced input versus the first UI retest, but increased wall time and output; it remained worse than original Hot Pick on all three totals. Its independent browser checks still passed. The experimental second-revision batching guidance was subsequently rolled back; its hashes and negative results remain preserved. The first revision is retained, with UI overhead unresolved. A separate post-hoc geometry audit at800/320px found zero input/button bounding-box deltas in every UI arm against the original seed. This exploratory audit did not alter the predeclared8/8 scores and found no layout-preservation advantage.

Interpretation

One run per arm/task is descriptive evidence, not statistically reliable proof of universal superiority. The first three tasks are dependency-free focused changes, deliberately testing unnecessary overhead; the fourth permits free dependencies for heterogeneous HTML extraction. This task mix must not be generalized to complex or unfamiliar integrations.

Input includes cached tokens; do not add the cached column again. Reasoning token fields are retained separately in JSON and not added a second time to output. These are API-reported session usage counts, not a dollar invoice. Session wall time includes startup, discovery, coding and the agent’s own checks. External acceptance-grader time is separately measured; setup of this evaluation harness is excluded.

Fresh process and directory do not provide OS-level isolation: sibling reads were prohibited by prompt and no such reads were observed. Global tool and skill metadata can appear in both session contexts; baseline was instructed not to invoke skills. Network and provider caching are uncontrolled. Improved treatment runs are new sessions using unchanged task prompts and updated Hot Pick, not repeated baseline measurements.

Quality is acceptance behavior coverage, not aesthetic quality, maintainability, security certification or user preference. Original failures and negative outcomes are retained. No claim of causal effect beyond this small sample is made.
