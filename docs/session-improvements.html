Improve the losses, not the claims

Actual work date: 2026-11-11. Git display dates follow a separate documented weekend policy.

Observed problem

In independent sessions on a standard-library CSV task, both arms passed 12 held-out checks. Hot Pick nevertheless spent more time and tokens routing, rejecting unrelated skills, inspecting CPython and reading long reference material. A small dependency-free pagination fix showed a similar discovery cascade. These observations justify reducing unnecessary tool use; they do not prove external expertise is generally unhelpful.

Implemented changes

  1. Caller-owned direct-work decision before network access: require a reason and concrete planned checks, record a trace, and explicitly report no selected external project.
  2. Literal, bounded excerpts for long supporting source documents: preserve commit/blob pins, line numbers and truncation indicators. A selected skill's complete entrypoint still needs to be read.
  3. Decode common folded/quoted SKILL.md description scalars so YAML markers such as >- cannot replace actual descriptions. Refresh cached profiles from already-cached instructions without re-fetching unchanged repositories; preserve only source-pin-matched semantic review.

Evaluation boundaries

Original runs keep the original source snapshot. Improved sessions use fresh task directories and the same task/arm prompts; they receive no intended answer or instruction to choose a particular decision. Held-out tests were declared before runs. Process wall time and actual CLI usage are reported separately from independent grader time. Cached input is a subset of input tokens, not an extra quantity; output/reasoning counts are not added twice or converted to dollars.

One run per condition/task is exploratory evidence, not a statistical superiority claim. Task fixtures, runtime caching and installed tool context limit generalization. An additional dependency-allowed HTML extraction pair checks a setting where external tooling is more plausible.

What the retests actually showed

The first revision's CSV session used bounded reads but still inspected an additional full source file: total time and uncached input/output did not improve. Pagination stopped after rejecting candidates instead of continuing to unrelated repositories, reducing observed time and tokens while preserving 12/12 checks; it remained slower and more expensive than the baseline. None of the three first-revision sessions selected the zero-network direct-work path, so its autonomous adoption is not demonstrated.

First-revision UI time decreased but input tokens increased substantially alongside 13 CUA calls. A second experimental instruction to batch deterministic verification was tested in a fresh UI session; it did not beat the original Hot Pick session overall and was removed from the final skill. Both unsuccessful revisions remain in the full report. All 12 runs passed their predeclared checks; exploratory UI geometry checks also found no difference. No quality-superiority or general efficiency claim is justified.

85 local tests and skill validation passed. Date-policy tooling is verified separately in an isolated temporary repository, including tree/identity/message preservation, recoverable backup, guarded commits and push-date checks.
