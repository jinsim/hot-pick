Task-aware retrieval controls

2026-11-11. Current primary sources support on-demand tool discovery and progressive disclosure rather than loading every tool definition. Sources: Anthropic advanced tool use, Vercel Agent Skills guide. These establish a direction, not a complete survey of the current AI market or proof of Hot Pick performance.

Observed product failure: a request about statistical ranking retrieved advertising analysis and PR triage because generic words matched. The agent correctly rejected them, but retrieval should let the agent express decisive requirements.

Implemented

  • Required normalized terms: all must occur in indexed evidence.
  • Case-insensitive exact repository exclusions.
  • Minimum query-term coverage between zero and one.
  • Optional repository diversity cap of one to three results.
  • Filters and eligible counts retained in the decision trace; no silent relaxation.

Existing requests preserve their previous defaults and popularity tie-break. Inputs are validated. Free-only collection, local intent interpretation and no internal LLM calls remain unchanged.

Verification

73 tests pass. New route tests exercise domain rejection, coverage, case-insensitive exclusions, repository diversity, no-match behavior and invalid inputs. The real cached catalog was queried with required statistics evidence and returned no matches rather than unrelated recommendations. This is an honest coverage gap, not proof that relevant projects do not exist. GitHub discovery remains the fallback.

Limits and next work

These are lexical controls chosen by the caller; arbitrary natural-language constraints are not automatically enforced. The initial full-catalog transfer remains a latency bottleneck. A small versioned routing index with on-demand detailed profiles needs a separately validated publication/cache migration; it was not silently introduced in this change. No token-reduction or task-quality improvement percentage is claimed.
